# 联网搜索

开启后，涉及实时信息的问题会先联网检索，再结合结果回答，并标注来源。

**不需要任何 API Key** —— 直接抓取公开搜索结果。

---

## 开启方式

设置 → **联网搜索** → 打开「允许联网搜索」。

默认使用 **Bing**，可选 360 搜索或搜狗。设置里有「测试搜索」可立刻验证是否可用。

---

## 什么时候会自动联网

不是每句话都搜——那样又慢又费流量。只在问题**涉及实时信息**时才查：

| 会联网 | 例子 |
| --- | --- |
| 时效词 | "最新的…"、"今天…"、"目前"、"最近" |
| 事实查询 | "…是什么"、"多少钱"、"天气"、"在哪" |
| 新闻动态 | "…发布了吗"、"有什么进展" |
| 明确要求 | "搜一下…"、"帮我查…" |
| 实时数据 | 比分、排名、票房、榜单 |

| 不会联网 | 例子 |
| --- | --- |
| 日常闲聊 | "你好"、"陪我聊聊" |
| 写作与改写 | "帮我写个邮件" |
| 代码与知识 | "解释一下什么是闭包" |
| 基于前文的问题 | "上面那段再改改" |

## 它是怎么工作的

```
你提问
  ↓
关键词判断是否需要联网（不需要 → 直接回答）
  ↓
原生层抓取搜索结果页（WebView 里 fetch 会被 CORS 拦，所以走原生）
  ↓
解析 HTML 提取 标题 / 链接 / 摘要
  ↓
作为「联网搜索结果」插入对话上下文
  ↓
模型结合结果作答，并标注来源编号
```

### 为什么在原生层抓取

搜索站点不返回 CORS 头，WebView 里直接 `fetch` 会被浏览器拦截。
原生 HTTP 没有这个限制，而且能设置完整请求头（部分站点会校验 UA）。

### 为什么不用搜索 API

主流的搜索 API（博查、Tavily、Serper 等）都要申请 Key、有配额与计费。
为了让你**装上就能用**，这里直接抓公开结果页。

代价是解析依赖页面结构，站点改版可能失效。因此内置三个引擎互为备份，
并且「测试搜索」能立刻看出哪个可用。

---

## 搜索失败会怎样

**不会影响对话**。搜索只是增强：

- 搜不到 → 照常回答，但会说明这可能不是最新情况
- 引擎失效 → 换一个引擎，或用「测试搜索」确认哪个可用
- 网络不通 → 同上

---

## 实测情况

`tools/verify-search.mjs` 会对每个引擎发真实请求并验证解析：

```sh
node tools/verify-search.mjs
```

当前结果（2026-10）：

| 引擎 | 状态 |
| --- | --- |
| Bing | ✓ 可用，中文结果质量好 |
| 360 搜索 | ✓ 可用，结果条数多 |
| 搜狗 | ✓ 可用，偶尔条目较少 |

Mojeek 对脚本请求返回 403、DuckDuckGo 与多数 SearXNG 实例在当前网络下不可达，
因此没有列入选项。

如果哪天发现搜索总是失败，先跑一下上面这个脚本，就能定位是网络问题还是站点改版。

---

## 隐私说明

- 搜索时，**你的查询词会发送给所选搜索引擎**（Bing / 360 / 搜狗）
- 搜索请求由手机直接发起，不经过本项目作者的服务器
- 检索结果会临时加入本次对话的上下文发给 DeepSeek，用于生成回答
- 不开启联网搜索时，不会有任何搜索请求

## 人设的影响

开启联网后，Fairy 的能力边界描述也同步更新了：

- **之前**：知道自己不能联网，被问实时信息时会说明并给替代方案
- **现在**：知道可以联网检索；如果这次没有检索到资料，
  她会基于自己的知识回答，并说明可能不是最新情况

关键约束仍然保留：**不许编造数据、链接或来源**。
她也不会再声称读了本地文件、执行了命令——那些确实做不到。
